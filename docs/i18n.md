# 共享 UI 文案与本地化

中文优先是仓库的默认约定，但还没有运行时切换语言的需求，因此这里没有引入 i18n 框架、Provider 或语言管理界面。共享字符串集中在一份类型化文案表里，组件直接取用。

## 约定

- 默认语言是 `zh-CN`，`en-US` 作为对照与采用方参考；两者键必须一致。
- 只有**多个组件复用**的字符串才进入 `src/lib/i18n.ts`。单个 feature 的文案留在该 feature 内，避免共享表膨胀。
- 可见文本、`aria-label`、`title`、`sr-only` 都从同一份文案取值，避免出现「看得见的是中文、读屏器读的是英文」。
- 日期、时间、数字一律交给平台 `Intl`，不手写拼接，也不使用 `toLocaleString('default')`。

## 添加字符串

1. 在 `catalog` 的 `zh-CN` 与 `en-US` 中同时加键；类型会检查两边键集合是否一致。
2. 组件里用 `t('yourKey')` 取值。
3. 键名用语义化 camelCase，按用途命名而非按页面命名（如 `clearSelection`、`noResults`）。

```ts
import { t } from '@/lib/i18n'

<span className='sr-only'>{t('close')}</span>
```

## 格式化

共享表同时导出三个 `Intl` 包装：

```ts
import { formatDateTime, formatMonthShort, formatNumber } from '@/lib/i18n'

formatMonthShort(new Date()) // 10月
formatDateTime(new Date()) // 2026年10月28日 09:05
formatNumber(1234.5) // 1,234.5
```

需要其他样式时，在调用处传 `Intl.NumberFormatOptions`，或在该模块补充包装，不要在组件里新建 `Intl` 实例。

## 测试

- `src/lib/i18n.test.ts` 校验两种语言的键集合一致、默认语言正确、`Intl` 输出随语言变化。
- 组件测试直接断言中文可见文本与可访问名称；`ConfirmDialog`、`SelectDropdown` 的默认文案已有覆盖。
- 新增共享字符串时，补一条断言即可，不需要为每个键单独写测试。

## 采用方如何扩展

- 直接修改 `src/lib/i18n.ts` 的 `catalog`，或把 `t` 换成自己的实现，组件不需要改动。
- 真正需要运行时切换语言时，把 `catalog` 提升为 Provider + locale 状态即可；现有 `t(key, locale)` 签名可以直接复用。
- 业务文案、后端返回的错误文案不要塞进共享表：前者归各自 feature，后者由服务端提供并直接展示。

## 边界

- Issue #4 的用户 CRUD 已单独完成中文化；本模块只负责共享默认文案与可访问标签，业务字符串仍留在各自 feature 中。
- 语言切换、复数规则、消息插值不在当前范围内；出现真实需求时再升级方案。
